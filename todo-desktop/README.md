# 事项便签

独立的 Windows 10 / 11 x64 事项与待办应用。沿用 Agent System 的浅色月历与紧凑事项列表风格，单独编译、单独运行，不依赖原应用或其数据。

## 使用

- 左侧栏只有「所有事项」「今天」和标签。项目 / 分区这一层暂时从界面撤掉，数据库和命令仍保留，以后需要再开。
- 所有事项默认按时间分组：已过期 / 今天 / 明天 / 本周内 / 以后 / 待安排，打开就知道接下来该管什么。
- 页头可以在「列表」「七天」「月历」三种布局间切换：七天是滚动的一周（可前后翻、点某天右下角 ＋ 直接在那天新增），月历点某天看当天安排；选择会被记住。今天视图固定列表。
- 七天和月历布局顶部有标签筛选：勾一个或多个标签，就只看带这些标签的事项（多个是并集），全部取消就是看全部；选择会记住。列表布局不受影响。
- 删除进回收站而不是直接消失：删完 8 秒内可点提示里的「撤销」（或按 `Ctrl+Z`），左栏「回收站」里也能恢复或彻底删除；回收站保留 30 天，超期自动清理。
- 「回顾」页看最近 14 天的完成柱状图、本周 / 本月完成数和连续天数。
- 每天首次打开会自动在 `backups/auto-<日期>.sqlite3` 留一份快照，只保留最近 7 份；schema 升级前另有一份 `tasks-<时间戳>.sqlite3`，两者互不覆盖。
- 左栏底部可设「提醒」时间（留空即关闭）：到点弹一条 Windows 通知，告诉你今天还有几项待办、几项已过期；同一天只提醒一次，应用需要保持在托盘里。
- 顶部有常驻的快速添加框：打字回车就存成「今天」的事项，输入框清空并保持焦点，可以连着敲；Esc 清空。
- 左下角可以勾「开机自动启动」：写入当前用户的 Run 项（`TaskNotes`，带 `--hidden`），开机后只在托盘里，不弹窗打扰。
- 关闭窗口只是收进托盘（托盘菜单：打开事项便签 / 打开桌面便签 / 退出）；彻底退出请用托盘「退出」或便签底部的「退出应用」。
- 事项支持多个标签、优先级 P1–P4、子事项、颜色、备注和日期范围；今天视图可拖拽调整顺序。
- 重复事项：在编辑器里选「每天」或「每隔 N 天」，可设「重复截止」（留空＝一直重复）。重复事项只保留一条，勾完当天就自动滚到下一次，每次勾选都留真实完成记录；撤销会把日期退回去。选了重复就不能再设结束日期。
- 所有新增入口默认安排在本地今天。结束日期留空表示单日；可选择日期范围，或清除日期留待安排。
- 今日待办按当天日期筛选。范围内每天显示；完成后保留勾选和划线，可取消完成或手动隐藏。移出今天仅排除当天；所有事项里可以重新加入今天。
- 点击“便签”打开独立桌面小窗口，只列今日待办；可置顶 / 取消置顶、直接勾选和返回主窗口。两个窗口实时联动，跨午夜和睡眠唤醒后按本地日期更新。
- 便签打开时关闭主窗口会继续保留便签；关闭最后一个可见窗口或点击便签底部“退出应用”会结束程序。再次打开应用可唤回主窗口。

双击仓库根目录 **启动事项便签.cmd**，运行已经编译好的程序，不重新编译。没有 EXE 时会明确提示先构建。当前使用嵌入界面的 debug EXE；可单独运行，不需要 Node、Rust 或业务服务器，电脑须有 WebView2。

## 同步

左栏底部「数据同步」里填一次 Fine-grained Token（对该私有仓库 Contents 读写），之后点「立即同步」即可；Token 由 Rust 调用 Windows DPAPI 加密保存为 `sync-token.dpapi`，不进数据库、日志或仓库。

- 与主应用共用私有仓库 `Nitinool/Agent-System-data`，但用独立文件 `sync/v2/task-notes.json` 和独立凭据。
- 合并规则：按事项 `id` 对比 `updated_at`，新的那条整条胜出；两边独有的记录都会保留。删除以回收站记录的形式同步，不会在另一台「复活」。
- 每次同步前会先在 `backups/` 留一份快照；写入远端使用文件 sha，远端被别处改过会提示再同步一次。
- 默认手动同步；换电脑前先在这台同步，到另一台先同步再编辑。

## 数据

资料独立保存在 **%LOCALAPPDATA%/Task-Notes/tasks.sqlite3**（SQLite schema 4，正表化）。提醒时间与同步状态在同目录的 settings.json。不读取或写入 Agent-System-V2，不导入已有事项，不使用原应用的同步 Token 或远端文件。

项目、分区、完成历史、标签关联等表仍在库里，只是当前没有界面入口；删除事项会连带删除它的子事项。换版本前请自行备份，升级只在 schema 变化时发生。

schema 1 旧库首次打开会自动升级：先把数据库（含 WAL 内容）备份到 `backups/tasks-<时间戳>.sqlite3`，再在单事务里正表化；schema 2 → 3 只是给 tasks / task_completions 加列（重复规则与完成日期），同样先备份。旧「分类」迁成标签，旧事项进收件箱，日期范围与「加入 / 移出今天」的行为不变。升级失败会回滚并保留备份，不会带着半份数据继续用。

SQLite 事务保存；主窗口 / 便签共用一个后台资料服务，通过版本号拒绝过期写入，失败显示错误并保留编辑内容。完成 / 取消完成保留真实历史时间。MSIX 重定向目录会被拒绝，避免产生两份资料；请优先从文件资源管理器双击启动。

## 开发和验证

Node 24、Rust 1.99.1 MSVC、Windows C++ Build Tools / SDK 和 WebView2，与原工程使用相同工具链；本目录可以单独复制开发。没有对 ../desktop 的源码或运行依赖。

```powershell
npm ci
npm run desktop
# 编译可直接运行的程序，不生成安装包
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start.ps1 -Build
# 检查已有程序
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start.ps1 -CheckOnly
```

构建后将嵌入界面的程序复制到 bin/task-notes.exe，日常入口固定运行该文件；后续开发构建不会把它替换成依赖 Vite 的开发程序。开发模式即上面的 `npm run desktop`（或 `tools/start.ps1 -Develop`），使用端口 1431，与原应用的端口不同。tools/start.ps1 含中文，保存为 UTF-8 BOM，兼容 Windows PowerShell 5.1。

```powershell
npm run build
npm test
cargo test --manifest-path src-tauri/Cargo.toml --no-default-features
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
npm run test:native
```

model.rs 为契约来源，npm run types 生成 src/bindings，不手工编辑。native-smoke.mjs 在工程内创建隔离 LOCALAPPDATA / WebView2 目录，只向临时库写固定样本，测试真实双窗口、日期、跨天、完成 / 撤销、删除和重启；不接触日常数据。测试截图和临时资料不提交。
