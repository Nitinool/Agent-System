# 个人记录（Windows 原型）

按天回看前台窗口的时间段、程序、标题和前台停留时长。Python 标准库实现，无第三方 Python 依赖。

左侧紧凑菜单包含“记录信息”“求职一览”“事项管理”“项目管理”和“财务管理”。切换页面不会暂停正在进行的行为采集，左侧底部显示当前记录状态。

## 启动

安装包含 Tkinter 的 Python 3.10 或更新版本，在此目录运行：

```powershell
python activity_logger.py
```

也可以双击 `启动行为日志.cmd`。脚本优先使用全局安装的 `C:\Program Files\Python310\python.exe`，再尝试 `py -3.10` 和可用的 `python`，最后才尝试 Codex 附带的 Python。每个候选环境都会实际执行检测，确认 Python 版本以及 Tkinter、SQLite 可用，跳过无法运行的 Windows 应用执行别名。独立分发给其他电脑时应准备 Python 环境或打包安装程序。

可以运行 `启动行为日志.cmd --check-runtime`，只检查启动环境，不打开窗口或开始采集。

点击“开始记录”，然后切换到浏览器、游戏或 Codex。最小化日志窗口后仍然记录；点击“暂停记录”或关闭窗口停止记录。每次打开软件都需要手动开始。

更新代码后，先关闭旧版日志窗口，再重新双击启动脚本。

两台电脑轮流开发的流程见 [开发交接.md](开发交接.md)：通过 [Agent-System](https://github.com/Nitinool/Agent-System) 仓库同步代码和交接文档，每台电脑分别安装 Python。本地日志和数据库不进入仓库。

## 两台电脑同步数据

源代码与运行数据使用两个仓库：代码在 Agent-System；手动录入的数据在私有仓库 [Agent-System-data](https://github.com/Nitinool/Agent-System-data)。每台电脑的 SQLite 数据库仍在本机。另一台电脑只需克隆代码仓库、安装 Python、启动软件，再使用“数据同步”获取共享记录，不需要手动复制数据库或克隆数据仓库。

1. 更新代码后关闭旧窗口，重新启动。点击左侧底部“数据同步…”。
2. 点击“创建 Token”，在 GitHub 创建 Fine-grained personal access token。Repository access 仅选择 **Agent-System-data**，Repository permissions 的 **Contents** 选择 **Read and write**；Metadata 保留默认读取权限。令牌可设到期时间。
3. 将 Token 填入软件，点击“立即同步”。勾选“在本机记住”后，凭据使用 Windows DPAPI 按当前用户加密，保存在忽略提交的 `data/sync-token.dpapi`，不进入两个 GitHub 仓库。也可以不勾选，仅在本次运行使用。
4. 另一台电脑同样配置一次 Token，推荐每台分别创建。之后输入框留空即可复用已保存的凭据；更换 Windows 用户或电脑时重新配置，不复制 Token 文件。
5. 换电脑前确认侧栏显示“待同步 0 条”且本次同步成功；另一台电脑打开后先同步，再录入数据。离线时仍能正常使用。

侧栏持续显示待同步条数、远端检查 / 同步结果、上次完成时间和手动 / 自动模式，无需打开设置；约每 3 秒刷新一次。

同步设置提供两个本机选项：

- **启动时检查远端更新**：默认开启。有已保存的 Token 时，启动后在后台检查；手动模式只提示远端是否有更新，点击“立即同步”后才合并。没有 Token 时不发起请求。
- **自动同步**：默认关闭。开启后启动时自动同步；停止修改约 5–10 秒后同步本机变化，并每 5 分钟检查和合并远端更新。选项保存在本机 `data/sync-settings.json`，两台电脑分别设置。未记住的 Token 仅在本次运行可用，重启后需重新填写。

自动同步遇到同一记录冲突会暂停，在侧栏显示冲突数量；打开“数据同步…”并点击“立即同步”，逐条选择后恢复。网络失败保留本地内容，自动模式从约 30 秒开始逐步延长重试间隔，最长 5 分钟。打开事项、项目等编辑窗口时会延后自动同步；下载或上传期间已经保存的修改仍会阻止本地覆盖。设置窗口可以关闭，后台任务与侧栏状态继续运行。关闭软件会停止后续同步，未完成的同步下次再重试。

首次交付已使用已连接的 GitHub 服务把本机当前共享记录上传到私有仓库，并记录同步基线。**软件自身的访问权限仍需按上述步骤在每台电脑配置**，它不会使用 Codex 连接器的登录凭据。

同步范围：求职投递（含公司、岗位、链接和备注）、事项、各日期的今日待办关联、项目、里程碑、验收与成果说明、真实完成和重新打开记录，以及财务账目（含副业来源、待结算状态和实际到账 / 支付日期）。公司名称随投递记录同步，空公司的下拉历史仅保留在本机。前台窗口行为日志、活动分类和 CSV 不同步。

同步本轮项目与日期范围前，两台电脑都应更新代码并关闭旧窗口后重启。项目 / 事项记录使用同步格式版本 3，新版兼容版本 1 / 2；旧版会拒绝新格式并保留本机内容。

首次同步财务账目前，两台电脑都应更新代码并关闭旧窗口后重启。含财务记录或其删除标记的同步文件使用格式版本 2，新版仍可读取旧版本 1；旧版软件会停止读取新格式，保留本机内容。

每条记录使用全局编号，删除保留标记。同一条记录两边都修改时，显示本机 / 远端版本，逐条选择保留哪份，也可以取消整次同步；事项的待办日期和完成历史与事项一起选择。独立新增记录可以合并；分别新建的同名项目会停止同步并提示先改名，避免误合并两个项目。远端写入使用文件 SHA 检查，遇到并发修改或网络超时可重新点击同步。若上传期间本地发生修改，软件保留本地内容及旧基线，要求再次同步。

侧栏和设置窗口显示待同步记录数和上次完成时间。接收改变前自动备份到 `data/backups/before-sync-*.sqlite3`；导入、关联检查和同步基线在同一事务内完成，写入失败回滚。请通过软件删除记录，不手动覆盖 `sync/records.json` 或删掉标记；删除同步不会清除 Git 历史里的旧版本。仓库必须为私有，读取与上传前都会检查。

同步仍使用单个 JSON 文件，上限 900 KB，超过时停止同步并保留本地数据；尚未实现行为日志分批上传、附件或远端历史恢复界面。GitHub Token 与 Contents API 的权限说明见 [GitHub 官方文档](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents)。

## 按天查看和统计

- 日期默认今天。使用“前一天”“后一天”“今天”，或输入 `YYYY-MM-DD` 后点击“查看” / 按回车。
- 每段显示开始、结束或最近采样时间、累计停留时长、应用、窗口标题和状态。进行中的时长每五次采样刷新，切换窗口时立即刷新。
- 默认勾选“合并相邻同一窗口（间隔 ≤ 2 分钟）”：短暂查看日志后返回同一应用和标题，合并显示为一行，状态注明原始段数。停留时长仅把各段相加，切到日志软件期间不计入该应用；双击可查看每个原始时间段。取消勾选即可查看原始拆分记录。
- 只有确认查看日志的短暂中断才合并。暂停、锁屏、睡眠、排除进程、无法读取窗口、其他应用和长间隔会阻止合并。
- 顶部汇总当天前台停留、锁屏 / 会话断开时长，以及停留最多的五个应用。汇总使用当天全部时间段，表格显示最新 1000 段。
- 跨午夜的时间段按当天范围显示和统计。原始时间段仍完整保存，全部导出保留完整段，当天导出按当天范围裁切。
- “导出当天 CSV”只导出所选日期；“导出全部 CSV”导出整个数据库。导出跟随合并选项，取消勾选可导出原始记录。Excel 可直接打开，包含开始、结束、停留秒数、状态、说明及原始段数。

## 分类、搜索和图表

在“活动时间线”里选中记录，选择“开发、学习、求职、娱乐、沟通、其他、未分类”，点击“应用到选中记录”。支持 Ctrl / Shift 多选；修改合并行会修改其中所有原始段。分类保存在独立的 `classifications` 表，不改写原始窗口标题和时长。重新打开后仍保留，选“未分类”可以撤销分类。当前不自动猜测活动用途。

跨午夜的一条原始记录共用同一个分类，修改会同时影响前后两天的对应部分。不同分类的记录不会合并。CSV 包含“分类”列。

搜索支持窗口标题、应用和进程名称，可以与应用、分类筛选一起使用。筛选只影响时间线列表，顶部汇总、分析图和日期导出仍使用所选日期的全部记录。

“分类分析”页包含：

- **分类时长图**：各分类累计前台时长和占比；“未分类”也计入总时长。占比的分母是当天已记录的前台时长，不是 24 小时。点击分类条可跳回时间线并筛选该分类。
- **24 小时活动分布**：按原始时间段和分类绘制色块，保留查看日志等造成的空白，不把合并行的整个跨度画成连续活动。锁屏 / 会话断开、已识别的采集间隔使用单独的行；移到色块上可查看时间、应用及标题。
- **分类覆盖率**：已分类前台时长占全部前台时长的比例。

图表空白表示没有采集到前台活动，不代表睡眠、休息或任何具体生活活动。电脑以外的活动暂未记录，视频后台播放时长也暂未采集。

## 求职一览

1. 点击左侧“求职一览”，再点击“新增已投岗位”。
2. 在同一个窗口填写公司和岗位名称。输入时自动显示匹配的历史名称，优先显示开头匹配项，也支持名称中间的文字及英文大小写匹配。点选候选项，或按上下方向键选择、回车确认；按 Esc 收起候选，Tab 切换字段。仍可直接填写新名称，点击下拉箭头可查看完整历史。
3. 填写投递日期、进度，可选填招聘页面链接和备注。日期默认今天，格式为 `YYYY-MM-DD`。
4. 每条投递占表格一行，显示公司、岗位、日期、进度、链接和备注。双击或选中后点击“编辑”，可修改全部字段，包括这条投递所属的公司。

进度支持“已投递、笔试中、面试中、已获 Offer、已拒绝、已撤回”。选中记录后可以打开链接或删除，删除会先确认。输入新公司时会自动保存公司名称，输入已有公司时会复用该公司（忽略首尾空格和英文大小写）。保存失败不会留下未完成的公司记录。

顶部显示已投公司数、岗位数、面试中岗位数和 Offer 数。公司数按投递记录去重；同公司三个岗位计为一家公司、三个岗位。已拒绝或撤回的记录仍保留在累计投递数量中。

搜索支持公司、岗位和备注，可与进度筛选组合使用。顶部数量始终统计全部记录，表格右下角显示筛选后的条数。保存后会清除筛选并选中该条记录。列表按投递日期从新到旧排列。

求职信息手动录入，保存在同一个本地数据库中，重启后保留；行为日志 CSV 仍导出行为记录。当前没有自动读取招聘网站或发送简历。

## 事项管理

左侧用月历查看全部事项，右侧固定显示今天的待办。两侧初始宽度约为 65% / 35%，可拖动中间分隔线调整。

- 点击“新增事项”，填写名称、安排日期、分类和备注，可选择所属项目、类型、状态和优先级，以及勾选“加入今日待办”。日期默认当前选中的日历日期，也可以留空。
- 点击日历日期，下方显示当天全部事项；使用左右按钮切换月份，“今天”回到今天。日期格显示部分事项名称及其余数量，完整名称和备注可通过下方列表及编辑窗口查看。
- 双击日历日期可新增当天事项；日历获得焦点后，方向键移动日期，回车新增。
- 选中下方事项可以编辑、删除或“安排今天”。点击完成列的方框、按空格，或勾选右侧待办，可切换完成状态；状态在日历、日期列表和今日待办中同步。
- 右侧输入名称后点击“＋”或按回车，直接新增今天的事项并加入今日待办。每条待办提供编辑和移出操作，多条待办可滚动查看。
- “移出”只取消今天的安排，原事项仍留在日历中；“删除”会在确认后删除事项及其所有日期的待办关联。
- 今日待办按实际日期保存，浏览其他月份不改变右侧日期。软件跨过午夜后会更新今日清单，未完成事项保留在原来的安排日期，需要时可再次“安排今天”。
- 点击“待安排”查看没有日期的事项。对待安排事项点击“安排今天”，会同时设置今天的安排日期；已有安排日期的事项加入今天时保留原日期。

安排日期与今日待办关联分别保存，因此可以把其他日期的事项临时加入今天，而不改写原来的安排日期。事项共用同一份状态、优先级和备注，尚未加入重复事项、提醒或按小时排程。所有信息保存在本地，关闭后重新打开仍保留。

## 项目管理和优先级

左侧按 Active、Planning、Archive 分组，可折叠展开。搜索支持项目名称、目标和编号；保留新增、编辑、确认后删除。项目可设置紧急 / 高 / 普通 / 低优先级，组内按优先级排序。旧项目的进行中、暂停、已完成分别显示为三组，状态切换不会自动改变事项状态或取消安排。

每个项目显示固定编号，例如 `[P4A18F921]`。编号由项目全局身份生成，随同步保持一致，不使用容易在两台电脑上碰撞的本地行号。删除项目后，其事项保留并解除项目关联，待办不再显示项目编号。

右侧可直接修改项目标题、目标、优先级和项目类型，状态下拉可切换分组。目标型显示事项完成比例与完成数；探索型目标与阶段可选，不显示百分比，保留完成数量。进度统计选中项目的所有事项，不代表目标自动验收。

- 阶段默认显示“阶段 n · 自定义标题”，可折叠，标题和目标可直接编辑；新增或删除阶段后事项保留。阶段所有事项完成后仍需确认验收，重新打开或新增未完成事项会清除验收标记。
- 顶部填写事项名称、选择所属阶段，点击“＋事项”或回车新增。所有阶段的事项在同一工作区显示；事项名称、优先级和状态直接修改，不显示类型列。
- 点击事项的“笔记”展开行内编辑区，停止输入约 800 毫秒或离开字段时保存，并显示保存状态；收起后恢复普通事项行。长笔记可打开全览。“更多设置”保留更换所属项目 / 阶段、验收条件、成果说明等原编辑功能。
- 完成状态与日历、今日待办共用同一事项，保留真实完成事件，可撤销。编辑失败时保留草稿并阻止离开页面；切换页面或关闭软件前尝试保存。自动同步在行内编辑或草稿未保存时延后；手动同步也检查尚未保存的修改。

点击事项的日期按钮后，在底部安排单日或日期范围。今天默认单日；一周为今天起连续 7 天；一个月为今天起至下月同日的前一天，月底按下月最后一天裁切。自定义填写起止日期，结束留空表示单日。

范围内未完成事项每天自动出现在今日待办，标题前带项目编号；完成后退出，重新打开后在有效范围内恢复。范围结束后退出每日待办，仍留在项目中，可重新安排。“移出”仅跳过当天，“安排今天”可恢复；原有手动加入某一天的关联继续保留，不复制或每天新建事项。日历显示范围覆盖的日期。“清除安排”取消范围；其他日期的手动关联保持独立。

软件日常启动不初始化演示项目。完成事件、历史备注和旧阶段保留；本轮没有修改真实用户记录。

## 财务管理

金额均为人民币，内部按整数分保存。顶部按所选月份显示到账收入、已支付支出、收支结余，以及所有月份的待结算金额 / 笔数；月份可以输入 `YYYY-MM`，使用前后月、本月或全部切换。

- **记账流水**：点击“＋ 支出”或“＋ 收入”，填写金额、交易日期、分类和可选说明 / 备注；副业相关收入和支出填写同一个“副业来源”，普通收支可留空。分类和副业来源输入时自动显示匹配的历史候选，选择方式与公司 / 岗位相同；仍支持直接输入新值和完整历史下拉。说明留空时使用分类名称。支持双击编辑、确认后删除，以及搜索、收支、状态和来源筛选；筛选不改变完整月份的汇总。
- **副业统计**：每个来源占一行，显示所选月份到账收入、已支付支出、净额及全部待结算金额 / 笔数。来源忽略英文大小写进行汇总。净额是该期间到账收入减已支付支出，不是账户余额。双击来源可查看其流水。
- **待结算（全部月份）**：卖出后未收款时，点击“＋ 待结算收入”，填写预计到账金额、卖出日期和副业来源。待结算不计入到账收入或收支结余，跨月后仍保留在该清单中。

收到款项后选中记录，点击“确认到账”，核对实际到账金额与日期，保存后更新原账目，不再新增一笔收入。例如 9 月卖出、10 月到账，收入计入 10 月。交易日期保留原卖出日期。支出同样按实际支付日期统计。需要更正时可以编辑原记录；改回待结算会清除到账日期并从到账收入中移出。

当前按整笔结算，支持到账时修改实际金额，暂未实现分次收款。财务账目与副业统计使用同一份数据，记录和删除均随现有私有仓库同步；日常启动不创建演示账目。

## 数据和异常退出

此前重构已按要求清空旧日志及升级备份，不支持最早的旧时间点数据。本次项目功能新增 `projects`，扩展事项的项目、状态、优先级和类型字段，并允许安排日期留空。升级通过事务保留当前行为日志、分类、求职记录、事项及待办关联；已有事项优先级默认为普通，完成状态保留。

当前数据库版本为 7，在原有财务账目和项目数据基础上增加项目优先级、类型、固定身份及事项日期范围 / 当天跳过记录。升级保留已有业务记录、行为日志、分类和同步基线，失败会回滚表和版本修改。

每秒保存最近采样时间和已确认的停留时长。异常退出后，重启会将未完成的时间段标记为“采集中断”，结束于最后保存的采样，不计入软件关闭期间的时间。新版本同一数据库只允许一个采集窗口运行。

## 采集范围

- 每秒检查一次 Windows 前台窗口，在程序、进程实例或标题发生变化时结束当前段并开始新段。
- 浏览器通常把活动标签页标题显示在窗口标题中，因此切换标签页也会产生记录。
- 保存采样时的本地时间及 UTC 偏移、应用显示名称、进程文件名、窗口标题，以及累计前台停留时长。
- 软件自己的窗口不记录。可以输入要排除的进程文件名（逗号分隔、忽略大小写），设置即时生效，但不会删除既有记录；重启后需要重新填写。
- 查询 Windows 当前会话的锁定和连接状态；锁屏 / 断开期间单独记录，不计入应用前台停留。状态查询不可用时，结束当前应用段并等待恢复。
- 采样间隔超过 5 秒时，切断前后时间段，空白显示“睡眠 / 采集间隔”。系统时间发生跳变也会切断时间段。空白不归属任何应用。
- 数据保存在本目录的 `data/activity.sqlite3`（CSV 为 UTF-8 BOM，适合 Excel 查看）。
- 不采集键盘内容、截图、网页正文或浏览器 URL；行为日志不上传。手动录入的数据可通过“数据同步”上传到指定私有仓库；没有自动启动和隐藏后台服务。

## 局限

这是粗略的前台窗口时间线，不是完整操作历史。短于采样间隔的切换可能遗漏；标题变化可能来自软件自动更新。有些游戏或程序只提供固定或空标题。进程信息读取被拒绝时显示 PID 占位名称，不需要为了这个原型以管理员运行。

停留时长代表前台窗口的采样估计，不代表实际工作时间；当前不判断长时间无键鼠输入，因为看视频、读文章也可能没有输入。锁屏采用每秒查询，边界存在约一个采样周期误差；睡眠通过采样间隔识别，不能区分系统睡眠和程序长时间未响应，也可能漏掉很短的中断。

浏览器页面标题可以辅助辨认招聘页面，但尚未进行自动分类；Codex 的具体聊天名称是否可见取决于它的窗口标题。

日志可能包含页面标题里的个人信息，可通过暂停和排除进程控制后续采集。

依赖方向是“界面 → 应用服务 → 核心逻辑与存储”。Windows 读取器在启动时注入服务，核心逻辑不导入 Tkinter 或 Windows API。列表汇总与图表使用同一份每日快照，列表筛选不会修改全天统计。

增加活动分类时修改 `models.CATEGORIES` 和图表配色；调整采集边界时修改 `CapturePolicy`；调整刷新或合并阈值时修改 `ViewPolicy`。更换平台采集方式时实现 `ActivityReader`，更换采集存储时实现 `RecordingStore`。采集器支持注入时钟和进程编号，便于用固定样本测试。

新增离线生活记录或分类规则时，优先放在应用服务和独立业务模块中，再由界面调用。业务数据库格式为 7，版本 1–6 会通过事务升级；其他不受支持的版本会拒绝打开。同步读取独立的版本 1 / 2 / 3 文件格式，有项目或事项（含删除标记）时写版本 3，仅财务时写版本 2，其他记录写版本 1；`sync_entities` / `sync_state` 辅助表在应用服务初始化时补齐编号及插入、删除触发器，不改写现有业务表。
